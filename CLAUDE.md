# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SatLedger (satledger.com): a client-side Bitcoin portfolio tracker. No backend. The whole app is
one HTML file; data lives in `localStorage`, with optional Google Drive sync (appDataFolder).

## Project Rules

- This is an existing production application. Preserve existing functionality.
- Never create duplicate transaction storage.
- Existing Bitcoin transaction records are authoritative.
- Preserve existing CoinLedger export behavior.
- Preserve exact Bitcoin/satoshi precision.
- Internal wallet transfers must never be counted as acquisitions or disposals.
- Market analytics and tax accounting are separate domains.
- Use existing Cloudflare architecture unless there is a documented reason to change it.
- Run typecheck, tests, and production build after meaningful implementation phases.
- Product specification: docs/specs/bitcoin-market-analytics.md

In this repo those three steps are `npm run check` (JSX parse — there is no TypeScript),
`npm test`, and `npm run build`.

The specification was written for a Worker/TypeScript app and does not match this repository.
The approved design for it is `docs/market-analytics.md` (which wins where the two disagree),
and it is built one phase at a time from `docs/market-implementation-plan.md`.

## Source vs generated — the one rule

- **Edit `app.dev.html`. Never edit `app.html` or `version.json`** — both are generated by
  `npm run build` (`tools/build.mjs`).
- **Commit `app.html` and `version.json` with every change to `app.dev.html`.** `npm test` fails
  if they are stale.
- **Pushing to `main` deploys.** Cloudflare Pages publishes the repo root with no build command,
  which is why the build output is committed.

`app.dev.html` runs as-is in a browser (React 18 UMD + in-browser Babel). The build compiles the
`<script type="text/babel">` block with esbuild, drops the Babel tag, stamps a content-hash build
id into the `__SATLEDGER_BUILD_ID__` placeholder (also written to `version.json`, which open tabs
poll to offer a reload), and rewrites the meta CSP `script-src` to hashes of the inline scripts.
Consequence: any new inline `<script>` or CDN script must be accounted for in `tools/build.mjs`
(it asserts exactly 2 unpkg scripts after removing Babel).

## Commands

```bash
npm install            # devDependencies only (esbuild, sharp, qrcode)
npm run build          # app.dev.html → app.html + version.json
npm run check          # parse the JSX block; a syntax error there = blank page
npm test               # check + build:check + pure-function tests (seconds, no browser)
npm run test:browser   # headless Chrome end-to-end smoke test (tests app.html by default)
npm run test:sw        # service worker behind Cloudflare-style /app.html → /app redirects
npm run test:all
```

- Single test file: `node tools/test/lots.mjs` (also `helpers.mjs`, `moving-average.mjs`, and for
  the Market `market-data.mjs`, `market-indicators.mjs`, `market-prefs.mjs`,
  `market-personal.mjs`). There is no test framework; each file is a standalone script that exits
  non-zero on failure.
- `tools/test/fixtures/` holds the CoinLedger golden input and CSVs (the browser test compares the
  export byte-for-byte — never regenerate them to make a test pass) and a real Coinbase daily-candle
  slice. The browser test answers every Coinbase request itself through the DevTools `Fetch`
  domain; no Market test touches the real network.
- Browser test against the source instead of the build:
  `SATLEDGER_PAGE=app.dev.html npm run test:browser` (PowerShell: `$env:SATLEDGER_PAGE='app.dev.html'`).
- Browser tests drive Chrome/Edge over the DevTools protocol (`tools/test/lib/harness.mjs`), and
  skip with exit 0 if none is found — set `CHROME_PATH`. A skip is not a pass.
- `npm run images` / `npm run qr` regenerate logo variants and Tip Jar QR PNGs.
- `node tools/backfill-reward-usd.mjs` — offline reward-USD backfill on a backup file (dry run by
  default, never modifies its input).

## Layout of `app.dev.html` (~12,000 lines)

1. **Head scripts (plain JS, not Babel)** — theme bootstrap, the `GDriveSync` module (OAuth via
   Google Identity Services, Drive REST), the boot watchdog / crash page with "Download my data",
   and the build-id update check. These are the hashed inline scripts.
2. **CSS** — theming through custom properties (light/dark).
3. **`<script type="text/babel">`** — everything else:
   - **Helper region**: from the line `const { useState, useEffect …` to the `─── SVG Icons`
     marker. Pure JS, no JSX. Holds date/number helpers, transaction ordering, reward USD logic,
     the lot engine, harvest, balance rules, the cost pool and CSV parsing. At its end, just
     before `─── SVG Icons`, the Market sections, each adding only the top-level names listed
     here: `Candles` (candle model, validation, aggregation, ranges/intervals,
     paging), `MarketData` (Coinbase provider, memory store, the caching/paging/backfill service),
     `Indicators` (SMA, EMA, RSI, MACD, Bollinger, ATR, volatility, returns, highs, `ATH_SEED`),
     the Market preference/URL helpers (`normalizeMarketPrefs`, `parseMarketHash`,
     `formatMarketHash`) and `PersonalMarket` (transactions → chart rows, balance history,
     Average Acquisition Price, context at a transaction, acquisition buckets).
   - Icons, `NAV_ITEMS`, `ErrorBoundary`, modal accessibility helpers.
   - `DashboardCharts` + `SVGChart` (hand-rolled SVG charting, no library).
   - The Market tab (component zone): `MarketCandleStore` (IndexedDB), `createChartAdapter` (the
     only code that touches Lightweight Charts), and `MarketView` with its sheets, tables and
     `MarketErrorBoundary`. Design: `docs/market-analytics.md` and the documents it links.
   - `App`: one large component holding state, the Drive push queue, sync reconciliation, CRUD,
     import/export, and the render tree.

### The helper region is a test contract

`tools/test/*.mjs` and `tools/lib/app-helpers.mjs` slice that region out of `app.dev.html` by
those two marker lines and evaluate it in Node with `new Function` — there is no duplicated copy
of the logic. Therefore:

- New pure logic that should be testable goes **inside** the region; it must not contain JSX or
  touch the DOM at definition time (`localStorage`/`crypto` only inside function bodies).
- Don't rename or move the two marker lines.
- To test a new helper, add its name to the `exported` list in the relevant test file.
- Code outside the region (e.g. `prepareTransactions`) is reachable only through the browser test.

## Domain rules that span the file

- **Balance rules live in one place** (`─── Balance rules` section: `txEffectOnWallet`,
  `txWalletDeltas`, `txPortfolioDelta`, `applyTxToCostPool`). Wallet holdings, running balances,
  stats and chart series all go through them — don't re-derive per call site. A Transfer's meaning
  depends on which ends are named (both = internal move, only the fee leaves).
- **Ordering**: transactions carry `datetimeUtc` + integer `sequence`; `date` stays the UTC day.
  Sort with `compareTx`. Legacy rows sit at 12:00:00 UTC. `migrateTxTimestamps` runs on every load
  path via `prepareTransactions`.
- **Two cost-basis models on purpose**: the Dashboard uses the average-cost pool; the Harvest tab
  uses per-wallet lots (`buildLots`, HIFO default, per-wallet `lotMethod`). They differ by design.
- **`excludeStats`** transactions skip cost basis and P&L but still count toward holdings.
- **Charts use all transactions and wallets**, not the active-wallet filter.
- **Versions**: `APP_VERSION` (UI) must match the footer in `index.html`.
  `BACKUP_SCHEMA_VERSION` and `VAULT_SCHEMA_VERSION` are data contracts — bump only for a real
  migration.
- Dates display as mm/dd/yyyy. Deletions use the in-app `ConfirmDialog`, not `window.confirm`.

## Storage and sync

Market candles are cached in IndexedDB database `satledger-market` (stores `candles`, `coverage`,
`meta`): public market data only, never synced or backed up, falling back to memory if IndexedDB
fails. Settings → Market Data clears it. Market view preferences live in `settings.market`, a
device view setting (in `DEVICE_VIEW_SETTING_KEYS`, so never pushed). No transaction-derived value
may reach IndexedDB, a request, the URL or a new storage key — the browser test asserts this.

`localStorage` is primary (`btc-tx-v2`, `btc-wallets`, `btc-settings`, `btc-vault`,
`btc-last-modified`, plus sync bookkeeping `btc-pending-push`, `btc-drive-seen-mtime`,
`btc-presync-backup`). Writes go through `safeSetItem` (quota-aware). The Drive token is in
`sessionStorage` and honours Google's ~1h `expires_in`, so it is always absent on a fresh launch.

Sync has a history of silent data loss; keep these invariants when touching it:

- Launch attempts a silent token grant and **pulls before anything can push**.
- `queueDrivePush` sets `btc-pending-push` **before** the signed-in check, so offline edits are
  marked dirty.
- Pushes are serialised; after an await, clear pending/dirty only if the payload is still the
  current one. Failed pushes retry with backoff; `drive_changed` is never retried.
- `findFile`/`pull` throw `drive_unreachable` on non-OK HTTP. `null` means "no file" and nothing else.
- Reconcile order: already-landed → dirty and remote moved (or no seen-mtime) → conflict dialog →
  dirty → push → only then compare stamps. Stamps come from `nextCommitStamp()` (monotonic).
- `pagehide`/`visibilitychange` pushes use `{urgent:true}` (keepalive, no `findFile` round-trip).
- View-only preferences are excluded from sync comparisons (`withoutViewSettings`).
- Sign-out keeps `btc-drive-seen-mtime` and `btc-pending-push`.

## Hosting and service worker

- `_headers` (Cloudflare Pages) sets what a meta CSP can't, notably `frame-ancestors 'none'`.
- Pages 308-redirects `/app.html` → `/app`; `sw.js` must pass redirects through rather than
  answer from cache. `npm run test:sw` covers this.
- Cloudflare injects an inline JS-detection script that the hash-based CSP blocks — expected.
- If you change caching logic or the precache list in `sw.js`, bump `CACHE_NAME`.
  `CRITICAL_URLS` is atomic on purpose; `OPTIONAL_URLS` are added one by one.
- CDN scripts are version-pinned with SRI; changing a version means updating the integrity hash
  and the matching URL in `sw.js`.
- `vendor/` holds the self-hosted Market chart library (Lightweight Charts, version in the
  filename, upstream `LICENSE`/`NOTICE` beside it, byte-exact via `.gitattributes`). It is loaded
  lazily by `loadChartLibrary()` under `script-src 'self'`, so `tools/build.mjs` does not see it.
  Changing the version means a new filename in `CHART_LIBRARY_SRC`, `sw.js` `OPTIONAL_URLS` and
  a `CACHE_NAME` bump.
